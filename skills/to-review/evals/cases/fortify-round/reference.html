Quick win: harden one failure (15 to 30 min)

Recommended: Fail when the Binding names a missing skill. It happened today, the cause is known and the test is exact.

Make wt:done name the process blocking it

A slow test hung 7+ minutes in a worktree, though a 60 s test timeout already exists. wt:done refused to tear down; cause of the hang unknown.

Analogy

A hotel door that will not lock but never says which guest is still inside.

Where it breaks down: The hang itself stays unexplained; this only fixes the cleanup.

Apply fail fast with actionable errors so that a stuck teardown names its blocker and finishes.

Before
  • Test hangs past the 60 s limit
  • wt:done refuses, names no process
  • Orchestrator hunts and kills it by hand
→
After
  • Test hangs past the 60 s limit
  • wt:done names the PID and ends the tree
  • Teardown completes
Evidence
  • Evidence. Observed failure 3 in decisions.md: vitest slow run hung 7+ minutes inside a Subagent worktree; wt:done refused; the Orchestrator killed the process tree by hand.
  • Evidence. vitest.slow.config.mts sets testTimeout: 60_000 since 2026-11-13, so the timeout did not stop this hang.
  • Unknown. Which test hung, why the timeout did not fire, the date and the minutes lost.
  • Weak. One incident, no cause. A different hang would still happen.
The change and its Enforcer

When a process runs inside the worktree, wt:done prints its PID and command and, with a flag, ends it, then tears down.

Enforcer: test:slow test that starts a background process in a temp worktree and asserts wt:done names and ends it (deterministic). Agent proposal.

Cost and door

15 to 30 min of one Subagent. Risk: ending a process the person still wants.

Two-way: revert the commit.

Impact

The Orchestrator no longer hunts for the process by hand. Hangs themselves still happen.

Make wt:new undo itself when it fails

When npm ci fails, wt:new leaves its branch and folder behind. A rerun stops with "branch already exists".

Analogy

Moving house with boxes half unpacked: you can neither go back nor start over cleanly.

Where it breaks down: A rollback only removes what the command itself created.

Apply all-or-nothing setup (+ idempotency) so that a failed wt:new leaves nothing and reruns cleanly.

Before
  • Branch created, worktree made
  • npm ci fails; branch and folder stay
  • Rerun: "branch already exists"; fix by hand
→
After
  • Branch created, worktree made
  • npm ci fails; rollback removes both
  • Rerun starts clean
Evidence
  • Evidence. Observed failure 1 in decisions.md: the first wt:new -- decisions/drive ended in a Node stack trace; the rerun said "branch already exists"; npm ci was rerun by hand in the half-made worktree.
  • Unknown. What made the install fail, and the minutes lost.
The change and its Enforcer

Wrap the steps of wt:new in a rollback that removes only what this call created.

Enforcer: test:slow test that injects an install failure and asserts no branch or folder remains (deterministic). Agent proposal.

Cost and door

15 to 30 min. More code to keep; the failure cause stays unexplained.

Two-way: revert the commit.

Impact

A failed setup is retried with one command, with no manual cleanup.

Fail preflight when main is marked bare

The git setting core.bare=true makes git treat a folder as storage only. It was found set on the real main checkout; cause unknown.

Analogy

A shop sign flipped from "Open" to "Warehouse only": the goods are inside, customers are turned away.

Where it breaks down: The sign is visible; this setting is invisible until something fails.

Apply shift left (+ detect drift) so that npm run preflight reports it before work starts.

Before
  • Setting flips to true, cause unknown
  • Git behaves oddly mid-run
  • Found and reset by hand
→
After
  • Setting flips to true, cause unknown
  • preflight fails: "core.bare=true"
  • Reset before anyone builds on it
Evidence
  • Evidence. Observed failure 2 in decisions.md: mid-run the main checkout was found with core.bare=true; a Subagent reset it to false.
  • Unknown. The cause (a test may have leaked into the real repo), the date, and the cost.
The change and its Enforcer

One check in npm run preflight: fail when core.bare is true in a checkout that has working files.

Enforcer: the preflight check plus a test with a temp repo (deterministic). It detects; it does not stop the leak. Agent proposal.

Cost and door

15 to 30 min. Low risk; the root cause stays open.

Two-way: delete the check.

Impact

The Operator hears about it at the start of a run, not mid-run.
